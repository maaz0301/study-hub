Lesson 1

Hello world

Every C# program needs an entry point. Console.WriteLine prints text to the screen.

The big idea

A program is a list of instructions the computer follows from top to bottom. C# needs to know **where to start**, and that place is a method called `Main`. The very first thing every programmer learns is how to make the program show text on the screen, because that is how your program talks to you. Think of `Console` as the black text window and `WriteLine` as 'write this line in that window'.

Step by step through the code

  1. class Program

    A class is a box that holds code. Every C# program lives inside at least one class. The name Program is just a convention. Everything between its curly braces { } belongs to this box.

  2. static void Main(string[] args)

    This is the entry point: the method the computer runs first. static means it can run without creating an object, void means it gives nothing back, Main is the required name, and string[] args would hold any words typed after the program name on the command line (we ignore them here).

  3. {  ...  }

    Curly braces mark where a block of code starts and ends. The code inside Main's braces runs line by line, from top to bottom, then the program ends.

  4. Console.WriteLine("Hello, World!");

    Console is the screen/keyboard window. WriteLine is a method (an action) that prints the text and then moves to a new line. The text sits inside double quotes. The ; at the end finishes the instruction, like a full stop in a sentence.

  5. Console.Write("Hello, ");

    Write is like WriteLine but it stays on the same line. The next thing printed continues right after it.

  6. Console.Write("again!");

    Continues on the same line, so the screen now shows Hello, again! on one line.

  7. Console.WriteLine();

    With nothing inside the brackets it prints just an empty line. It also moves the cursor to a fresh line, so later output starts clean.

  8. Console.ReadLine();

    Waits until you press Enter. Without it the window could close instantly after printing and you would never see the output.

Output you will see

Hello, World!
Hello, again!

Common mistakes

  • Forgetting the semicolon ; at the end of a statement (compile error).
  • Using single quotes for text. Single quotes are for ONE character; text needs double quotes.
  • Writing console.writeline in lowercase. C# is case-sensitive, so it must be Console.WriteLine.
  • Forgetting a closing } brace.
Show the full program (01_hello_world/Program.cs)
// TOPIC: Hello world
// Every C# program needs an entry point. Since C# 9 you can use "top-level statements":
// the code you write here becomes the Main method automatically.
//
// RUN:  dotnet run --project 01_hello_world
//       (or from inside this folder:  dotnet run)

class Program
{
    static void Main(string[] args)
    {
        // Console.WriteLine prints text to the screen and moves to a new line.
        Console.WriteLine("Hello, World!");

        // Console.Write prints text but stays on the same line.
        Console.Write("Hello, ");
        Console.Write("again!");
        Console.WriteLine(); // an empty WriteLine just adds a blank line

        Console.ReadLine();   // keeps the window open until you press Enter
    }
}

Lesson 2

Numeric data types

Whole-number types (byte, short, int, long) and decimal-point types (float, double, decimal).

The big idea

Every variable has a **type** that says what kind of value it holds. A variable is like a labelled box: the type decides the size and shape of the box. Small boxes save memory but can only hold small numbers; big boxes hold more. For everyday work you only need int (whole numbers) and double (decimals), plus decimal whenever money is involved.

Step by step through the code

  1. byte b = 255;

    byte is the smallest whole-number type. It only holds 0 to 255. The format is type name = value;, so we create a box called b and put 255 in it.

  2. short s = -32000;

    short holds about -32 thousand to +32 thousand, including negatives.

  3. int i = 2_000_000_000;

    int is the everyday whole number: about ±2.1 billion. The underscores are only a visual aid so you can read big numbers. C# ignores them.

  4. long l = 9_000_000_000_000L;

    long is for huge whole numbers. The L at the end tells C# 'this literal is a long', otherwise it would assume int and complain it is too big.

  5. float f = 3.14f;

    float holds decimals with about 7 digits of precision. The f suffix is required, because plain decimals are assumed to be double.

  6. double d = 3.141592653589793;

    double is the default for decimals: about 15 digits of precision. Use it for measurements, averages, etc.

  7. decimal m = 19.99m;

    decimal keeps 28 digits and does exact decimal math. The m suffix is required. Use it for money.

  8. Console.WriteLine($"byte {b}, short {s}, ...");

    The $ before the quote lets you put variables inside { } and have their value inserted into the text (see lesson 24).

  9. int.MinValue .. int.MaxValue

    Every numeric type knows its own limits. int.MaxValue is 2147483647. Going past the limit wraps around or errors, so pick a type that fits.

  10. 0.1 + 0.2  as double vs decimal

    Computers store double in binary, and 0.1 cannot be written exactly in binary (like 1/3 cannot be written exactly in decimal). So the double result prints 0.30000000000000004. decimal stores base-10 digits, so you get exactly 0.3. That is why money uses decimal.

Output you will see

byte 255, short -32000, int 2000000000, long 9000000000000
float 3.14, double 3.141592653589793, decimal 19.99
int range: -2147483648 .. 2147483647
0.1 + 0.2 as double  = 0.30000000000000004
0.1 + 0.2 as decimal = 0.3

Common mistakes

  • Writing float f = 3.14; without the f (compile error: double cannot become float automatically).
  • Using double for money and getting tiny rounding errors.
  • Storing a number too big for the type, e.g. 300 in a byte.
  • Forgetting the L on a big long literal.

//

//       (or from inside this folder:  dotnet run)

{

    {
        byte b = 255;                 // 0 .. 255
        short s = -32000;             // about -32 thousand .. +32 thousand

Lesson 3

Text based data types

char holds ONE character (single quotes). string holds a sequence of characters (double quotes).

The big idea

Text has two forms. A char is a single letter, digit or symbol. A string is a whole piece of text, made of many chars in a row. Strings also come with useful built-in abilities (length, change case, and many more) that you reach with a dot, e.g. word.Length.

Step by step through the code

  1. char letter = 'A';

    A char holds exactly one character, written in single quotes.

  2. string word = "Hello";

    A string holds text, written in double quotes. Even one letter in double quotes is a string, not a char.

  3. (int)letter

    A computer only stores numbers, so each character has a number (its Unicode code). (int) in front is a cast: it asks C# to treat the char as a number. 'A' is 65, 'a' is 97.

  4. word.Length

    A property of every string: the number of characters. 'Hello' has 5.

  5. word.ToUpper()  /  word.ToLower()

    Methods (actions, with brackets) that return a new string in all capitals or all lowercase. The original word is not changed, because strings can never be edited in place.

  6. "Tab:       [\t]"

    An escape sequence starts with a backslash \ and means a special character. \t inserts a tab (a wide gap).

  7. "Quote: [\"]"

    \" inserts a double quote inside a string. Without the backslash, the quote would end the string early.

  8. "Backslash: [\\]"

    To print one backslash you write two, because a single one means 'special character coming'.

  9. "Two lines:\nsecond line"

    \n starts a new line in the middle of a string.

Output you will see

char: A, as a number: 65
string: Hello, length: 5, upper: HELLO, lower: hello
Tab:       [	]
Quote:     ["]
Backslash: [\]
Two lines:
second line

Common mistakes

  • Using double quotes for a char: char c = "A"; is an error (it is a string).
  • Putting two letters in a char: 'AB'.
  • Expecting word.ToUpper() to change word. You must use the returned value.
  • Forgetting to double a backslash in a normal string.
Show the full program (03_text_types/Program.cs)
// TOPIC: Text based data types
// char holds ONE character (single quotes). string holds a sequence of characters (double quotes).
//
// RUN:  dotnet run --project 03_text_types
//       (or from inside this folder:  dotnet run)

class Program
{
    static void Main(string[] args)
    {
        char letter = 'A';
        string word = "Hello";

        // A char is really a number (its Unicode code) underneath.
        Console.WriteLine($"char: {letter}, as a number: {(int)letter}");

        // Strings have useful properties and methods.
        Console.WriteLine($"string: {word}, length: {word.Length}, upper: {word.ToUpper()}, lower: {word.ToLower()}");

        // Escape sequences start with a backslash and insert special characters.
        Console.WriteLine("Tab:       [\t]");
        Console.WriteLine("Quote:     [\"]");
        Console.WriteLine("Backslash: [\\]");
        Console.WriteLine("Two lines:\nsecond line");

        Console.ReadLine();   // keeps the window open until you press Enter
    }
}

Lesson 4

Converting string to numbers

Text typed by a user is always a string. To do math you must convert it to a number.

The big idea

The text "42" and the number 42 look alike but are different things to the computer: you can calculate with the number but not with the text. Everything a user types arrives as text, so you need to convert it before adding or comparing. And the opposite direction (number to text) is just as common when you want to display a result.

Step by step through the code

  1. string text = "42";

    A string that happens to contain digits. C# sees it only as text.

  2. int a = int.Parse(text);

    int.Parse reads the text and returns the whole number inside. Now a is the real number 42. If the text is not a valid number (like abc) it throws an exception and the program crashes.

  3. int b = Convert.ToInt32("58");

    The Convert class does the same job in another style. Both are fine for text you trust.

  4. double d = double.Parse("3.5");

    Every number type has its own Parse. This one reads a decimal.

  5. Console.WriteLine($"{a} + {b} = {a + b}");

    Now that both are real numbers, a + b is addition: 100.

  6. string back = (a * 2).ToString();

    ToString() goes the other way, number to text. (a * 2) is 84, and it becomes the text "84".

  7. "Glued, not added: " + "1" + "2"

    With strings, + means join, not add. "1" + "2" gives "12". This is the classic bug when you forget to convert user input.

Output you will see

42 + 58 = 100
double times two: 7
Number to string: 84
Glued, not added: 12

Common mistakes

  • Using Parse on text you do not control: int.Parse("abc") crashes. The safe version is TryParse (lesson 19).
  • Expecting "1" + "2" to be 3.
  • Parsing "3.5" with int.Parse (it is not a whole number).
Show the full program (04_string_to_number/Program.cs)
// TOPIC: Converting string to numbers
// Text typed by a user is always a string. To do math you must convert it to a number.
//
// RUN:  dotnet run --project 04_string_to_number
//       (or from inside this folder:  dotnet run)

class Program
{
    static void Main(string[] args)
    {
        string text = "42";

        int a = int.Parse(text);          // Parse: throws an exception if the text is not a valid number
        int b = Convert.ToInt32("58");    // Convert class: another way to do the same thing
        double d = double.Parse("3.5");   // works for decimals too

        Console.WriteLine($"{a} + {b} = {a + b}");
        Console.WriteLine($"double times two: {d * 2}");

        // Going the other way: number -> string with ToString().
        string back = (a * 2).ToString();
        Console.WriteLine("Number to string: " + back);

        // Without conversion, "+" on strings glues text together instead of adding.
        Console.WriteLine("Glued, not added: " + "1" + "2");

        Console.ReadLine();   // keeps the window open until you press Enter
    }
}

Lesson 5

Boolean data type

A bool holds only true or false. It is the result of every comparison and the input of every if.

The big idea

Programs constantly make decisions: is the user old enough? did the password match? A bool (named after George Boole) is the type that stores a yes/no answer, written true or false. Comparisons like 10 > 5 produce bools, and so do the logical operators that combine them.

Step by step through the code

  1. bool isRaining = true;

    Creates a variable that can only ever be true or false (lowercase, no quotes). Names that read like a question (isRaining, hasUmbrella) make code easy to read.

  2. bool hasUmbrella = false;

    The second flag. Together they describe a small situation.

  3. isRaining && !hasUmbrella

    && means AND: true only if both sides are true. ! means NOT: it flips true to false. So this reads 'it is raining AND I do not have an umbrella', which is true, meaning I will get wet.

  4. ||

    Not used here but worth knowing: || means OR, true if at least one side is true.

  5. 10 > 5

    A comparison. Comparisons never give numbers; they give a bool. Here: True.

  6. 3 == 4

    == (two equals signs) asks 'are these equal?'. The answer is False. A single = is different: it assigns a value.

Output you will see

Raining: True, has umbrella: False
Will get wet: True
10 > 5 is True
3 == 4 is False

Common mistakes

  • Writing = where you meant ==.
  • Writing "true" in quotes (that is a string, not a bool).
  • Capital letters: C# uses true, not True in code (though it prints as True).
Show the full program (05_boolean/Program.cs)
// TOPIC: Boolean data type
// A bool holds only true or false. It is the result of every comparison and the input of every if.
//
// RUN:  dotnet run --project 05_boolean
//       (or from inside this folder:  dotnet run)

class Program
{
    static void Main(string[] args)
    {
        bool isRaining = true;
        bool hasUmbrella = false;
        Console.WriteLine($"Raining: {isRaining}, has umbrella: {hasUmbrella}");

        // Logical operators combine bools: && (and), || (or), ! (not).
        bool willGetWet = isRaining && !hasUmbrella;
        Console.WriteLine($"Will get wet: {willGetWet}");

        // Comparisons produce bools.
        Console.WriteLine($"10 > 5 is {10 > 5}");
        Console.WriteLine($"3 == 4 is {3 == 4}");

        Console.ReadLine();   // keeps the window open until you press Enter
    }
}

Lesson 6

Operators

Operators perform work on values: arithmetic, compound assignment, increment, comparison, logical.

The big idea

An operator is a symbol that does something to values, like + does addition. The things it works on are called operands. This lesson is a tour of the main groups so you recognise each symbol.

Step by step through the code

  1. int a = 10, b = 3;

    Two variables of the same type declared in one line, separated by a comma.

  2. a + b,  a - b,  a * b

    Normal arithmetic: add, subtract, multiply (the star is multiplication). Results: 13, 7, 30.

  3. a / b

    Divide. Because both are int, C# also gives an int and throws away the fraction: 10 / 3 is 3, not 3.33.

  4. (double)a / b

    To keep decimals, cast one side to double first. Now it is decimal division: 3.33. :F2 shows 2 decimals.

  5. x += 2;  x *= 3;

    Compound assignment: shorthand. x += 2 means x = x + 2. Starting at 5: +2 gives 7, then ×3 gives 21.

  6. x++;

    Increment: add 1. (x-- subtracts 1.) 21 becomes 22.

  7. a == b,  a != b,  a >= b

    Comparison operators: equal, not equal, greater-or-equal (also <, >, <=). They produce a bool.

  8. a > 5 && b > 5

    AND: both must be true. 10>5 is true, 3>5 is false, so the result is False.

  9. a > 5 || b > 5

    OR: one is enough. Result: True.

  10. !(a > 5)

    NOT flips the result: !(True) is False.

Output you will see

a + b = 13
a - b = 7
a * b = 30
a / b = 3   (int / int drops the fraction!)
a / b = 3.33   (cast one side to double to keep it)
After += and *=: 21
After x++: 22
a == b: False, a != b: True, a >= b: True
a > 5 && b > 5: False
a > 5 || b > 5: True
!(a > 5): False

Common mistakes

  • Expecting 10 / 3 to be 3.33 with ints.
  • Mixing up && (AND) and || (OR).
  • Writing x =+ 2 instead of x += 2.
  • Confusing = (assign) with == (compare).
Show the full program (06_operators/Program.cs)
// TOPIC: Operators
// Operators perform work on values. Here are the main groups.
//
// RUN:  dotnet run --project 06_operators
//       (or from inside this folder:  dotnet run)

class Program
{
    static void Main(string[] args)
    {
        int a = 10, b = 3;

        // Arithmetic: + - * /
        Console.WriteLine($"a + b = {a + b}");
        Console.WriteLine($"a - b = {a - b}");
        Console.WriteLine($"a * b = {a * b}");
        Console.WriteLine($"a / b = {a / b}   (int / int drops the fraction!)");
        Console.WriteLine($"a / b = {(double)a / b:F2}   (cast one side to double to keep it)");

        // Compound assignment: shorthand for x = x + something.
        int x = 5;
        x += 2;   // x = x + 2  -> 7

        Console.WriteLine($"After += and *=: {x}");

        x++;
        Console.WriteLine($"After x++: {x}");

        // Comparison operators give a bool.
        Console.WriteLine($"a == b: {a == b}, a != b: {a != b}, a >= b: {a >= b}");

        // Logical operators.
        Console.WriteLine($"a > 5 && b > 5: {a > 5 && b > 5}");
        Console.WriteLine($"a > 5 || b > 5: {a > 5 || b > 5}");
        Console.WriteLine($"!(a > 5): {!(a > 5)}");

        Console.ReadLine();   // keeps the window open until you press Enter
    }
}

Lesson 7

Remainder (modulus) operator

The % operator gives what is left over after division.

The big idea

When you divide 10 by 3 you get 3 with 1 left over. The / operator gives you the 3 (for ints) and the % operator gives you the leftover 1. It is surprisingly useful: even/odd checks, wrapping around, splitting minutes into hours, and more.

Step by step through the code

  1. 10 % 3

    10 = 3 × 3 + 1, so the remainder is 1.

  2. 15 % 5

    5 fits into 15 exactly, nothing left over, so 0. A result of 0 means 'divides evenly'.

  3. -7 % 3

    With negatives, the sign of the answer follows the left-hand number, so the result is -1.

  4. int hours = totalMinutes / 60;

    Whole-number division tells you how many full hours fit in 135 minutes: 2.

  5. int minutes = totalMinutes % 60;

    The remainder is what is left after taking out full hours: 15. Together: 2h 15m.

  6. 8 % 2 == 0

    The classic even test. Any even number has remainder 0 when divided by 2; odd numbers have remainder 1.

Output you will see

10 % 3 = 1
15 % 5 = 0
-7 % 3 = -1
135 minutes = 2h 15m
Is 8 even? True

Common mistakes

  • Thinking % means percent.
  • Using % 0, which crashes (division by zero).
  • Forgetting the result is an int when both numbers are ints.
Show the full program (07_remainder/Program.cs)
// TOPIC: Remainder (modulus) operator
// The % operator gives what is left over after division.
//
// RUN:  dotnet run --project 07_remainder
//       (or from inside this folder:  dotnet run)

class Program
{
    static void Main(string[] args)
    {
        Console.WriteLine($"10 % 3 = {10 % 3}");   // 10 = 3*3 + 1
        Console.WriteLine($"15 % 5 = {15 % 5}");   // divides evenly, so 0
        Console.WriteLine($"-7 % 3 = {-7 % 3}");   // the sign follows the left-hand number

        // Classic use: split minutes into hours and minutes.
        int totalMinutes = 135;
        int hours = totalMinutes / 60;      // whole hours
        int minutes = totalMinutes % 60;    // minutes left over
        Console.WriteLine($"{totalMinutes} minutes = {hours}h {minutes}m");

        // Another classic use: even/odd check (n % 2 is 0 for even numbers).
        Console.WriteLine($"Is 8 even? {8 % 2 == 0}");

        Console.ReadLine();   // keeps the window open until you press Enter
    }
}

Run it: dotnet run --project 07_remainder

Lesson 8

var keyword

var lets the compiler work out the type from the value on the right.

The big idea

Writing the type every time can be repetitive. With var, you let the compiler look at the value and decide the type for you. It is not a 'can hold anything' variable (that would be risky). Once decided, the type is locked in.

Step by step through the code

  1. var n = 10;

    The compiler sees a whole number and makes n an int.

  2. var price = 9.99;

    A number with a decimal point: double.

  3. var name = "Ada";

    Quotes mean text: string.

  4. var flag = true;

    bool.

  5. n.GetType().Name

    Asks the variable what type it really has. The output (Int32, Double, String, Boolean) proves var still gave each a fixed type. Int32 is just the .NET name for int.

  6. // n = "text";

    Commented out because it would not compile: n is an int forever, so you cannot put text in it.

  7. var x;

    Also an error: with no value on the right, there is nothing to infer from.

Output you will see

10 is a Int32
9.99 is a Double
Ada is a String
True is a Boolean

Common mistakes

  • Thinking var makes a variable that can change type.
  • Declaring var x; without a value.
  • Using var when the type is not obvious (e.g. var r = Calculate();), which makes code harder to read.
Show the full program (08_var_keyword/Program.cs)
// TOPIC: var keyword
// "var" lets the compiler work out the type from the value on the right.
// The variable is still strongly typed; var is not an "any type" variable.
//
// RUN:  dotnet run --project 08_var_keyword
//       (or from inside this folder:  dotnet run)

class Program
{
    static void Main(string[] args)
    {
        var n = 10;          // int
        var price = 9.99;    // double
        var name = "Ada";    // string
        var flag = true;     // bool

        Console.WriteLine($"{n} is a {n.GetType().Name}");
        Console.WriteLine($"{price} is a {price.GetType().Name}");
        Console.WriteLine($"{name} is a {name.GetType().Name}");
        Console.WriteLine($"{flag} is a {flag.GetType().Name}");

        // The type is fixed after the first assignment, so this would NOT compile:
        // n = "text";

        // var needs a value to infer from, so "var x;" alone is also an error.
        // Tip: use var when the type is obvious from the right side, otherwise write the type.

        Console.ReadLine();   // keeps the window open until you press Enter
    }
}

Run it: dotnet run --project 08_var_keyword

Lesson 9

const keyword

A const is a value that can never change after it is declared.

The big idea

Lesson 12

Console Input/Output

Console.ReadLine() waits for the user to type a line and press Enter.

The big idea

Until now programs only talked. ReadLine lets the user talk back: the program pauses, the user types, presses Enter, and whatever they typed comes back to your code as a string. If there is no keyboard input at all (for example the program is run by a script) it returns null, which means 'nothing'.

Step by step through the code

  1. Console.Write("What is your name? ");

    Uses Write (not WriteLine) so the question and the user's answer stay on the same line.

  2. string name = Console.ReadLine() ?? "";

    ReadLine() pauses and returns what the user typed. The ?? operator means 'if the left side is null, use the right side instead', so we get an empty string rather than null.

  3. if (name == "") name = "stranger";

    If the user just pressed Enter, we substitute a default so the greeting still reads naturally.

  4. Console.Write("How old are you? ");

    Second question, same pattern.

  5. string ageText = Console.ReadLine() ?? "";

    The age also arrives as text, even if the user typed digits.

  6. int.TryParse(ageText, out int age);

    Converts that text to a real number safely (lesson 19). If the conversion fails, age stays 0 instead of crashing.

  7. Console.WriteLine($"Hello {name}, next year you will be {age + 1}.");

    Now age is a number, so age + 1 is real addition. With the input Ada and 30 you get 31.

  8. Console.Error.WriteLine("...");

    Writes to the separate error stream, used for diagnostics. In a normal window it looks the same, but scripts can separate it from normal output.

Output you will see

What is your name? How old are you? Hello Ada, next year you will be 31.
(this line was written to the error stream)

Common mistakes

  • Forgetting that ReadLine returns text, so age + 1 on text would glue, not add.
  • Not handling empty or invalid input.
  • Using WriteLine for the question, which pushes the answer to the next line.

Lesson 13

If statements

if runs a block only when a condition is true; else if and else handle the other cases.

The big idea

An if lets the program choose a path. You give it a question that is either true or false; if true, the block runs. You can chain extra questions with else if and a final catch-all else. The checks happen from top to bottom and the first one that is true wins; the rest are skipped.

Step by step through the code

  1. int score = 72;

    The value we are going to test.

  2. if (score >= 90) { ... }

    The condition goes in round brackets. 72 is not >= 90, so this block is skipped.

  3. else if (score >= 80) { ... }

    Only checked if the one above was false. 72 is not >= 80, so skipped.

  4. else if (score >= 70) { ... }

    72 >= 70 is true, so this block runs and prints Grade C. Everything below is skipped.

  5. else { Console.WriteLine("Fail"); }

    The catch-all: runs only if every condition above was false.

  6. if (score > 50 && score < 100)

    A separate if (not chained). && means both must be true: more than 50 AND less than 100. 72 qualifies.

  7. Console.WriteLine("Passed, but not perfect");

    Runs because the combined condition was true.

Output you will see

Grade C
Passed, but not perfect

Common mistakes

  • Putting a semicolon right after the condition: if (x > 3);.
  • Ordering conditions wrongly. Always test the most specific/highest first.
  • Using = instead of == in the condition.
  • Forgetting that a plain second if is independent of the first chain.

Lesson 14

Switch statements

A switch picks one branch based on the value of a single variable.

The big idea

When you compare one value against many fixed options (day 1 means Monday, day 2 means Tuesday, ...), a long chain of if / else if becomes messy. A switch lists the options neatly. C# also has a modern switch expression that produces a value in one go.

Step by step through the code

  1. int day = 3;

    The value we will test.

  2. switch (day)

    'Look at day and jump to the matching case.'

  3. case 1: Console.WriteLine("Monday"); break;

    If day is 1, run the lines below it until break. break ends the case; C# does not let you accidentally run into the next case.

  4. case 6: case 7:

    Two labels sharing one block: 6 or 7 both mean weekend.

  5. default:

    Runs when no case matched. Like the final else.

  6. string kind = day switch { 6 or 7 => "weekend", ... };

    The switch expression: it returns a value instead of running statements. The => arrow means 'gives'. or combines options.

  7. >= 1 and <= 5 => "weekday"

    Patterns can use ranges: 1 to 5 is a weekday. The words and / or combine patterns.

  8. _ => "invalid"

    The underscore means 'anything else', the expression's default.

Output you will see

Wednesday
Day 3 is a weekday

Common mistakes

  • Forgetting break (compile error in C#).
  • Forgetting the default case.
  • Using switch when you need to compare ranges with the old syntax (use the expression form).
Show the full program (14_switch_statements/Program.cs)
// TOPIC: Switch statements
// A switch picks one branch based on the value of a single variable. It is tidier than a long if/else chain.
//
// RUN:  dotnet run --project 14_switch_statements
//       (or from inside this folder:  dotnet run)

class Program
{
    static void Main(string[] args)
    {
        int day = 3;

        switch (day)
        {
            case 1:
                Console.WriteLine("Monday");
                break;                       // break ends the case (no fall-through in C#)
            case 2:
                Console.WriteLine("Tuesday");
                break;
            case 3:
                Console.WriteLine("Wednesday");
                break;
            case 6:
            case 7:                          // two cases can share one block
                Console.WriteLine("Weekend");
                break;
            default:                         // runs when nothing else matched
                Console.WriteLine("Unknown day");
                break;
        }

        // The modern "switch expression" returns a value and supports ranges (relational patterns).
        string kind = day switch
        {
            6 or 7 => "weekend",
            >= 1 and <= 5 => "weekday",
            _ => "invalid"                   // _ means "anything else"
        };
        Console.WriteLine($"Day {day} is a {kind}");

        Console.ReadLine();   // keeps the window open until you press Enter
    }
}

Lesson 15

For loops

A for loop repeats code a known number of times.

The big idea

A loop saves you from writing the same line over and over. The for loop is the one to use when you know (or can count) how many times to repeat. Its brackets hold three parts separated by semicolons: where to start; when to keep going; how to step.

Step by step through the code

  1. for (int i = 1; i <= 5; i++)

    Part 1 int i = 1: create a counter starting at 1. Part 2 i <= 5: keep looping while this is true. Part 3 i++: after each lap add 1 to i.

  2. Console.Write(i + " ");

    The body runs once per lap. It prints the counter and a space, so the output is 1 2 3 4 5.

  3. for (int i = 10; i >= 0; i -= 5)

    Counting down: start at 10, continue while i is at least 0, and subtract 5 each lap: 10, 5, 0.

  4. int sum = 0;

    A running total that starts at zero before the loop.

  5. sum += i;

    Each lap adds the current i to the total. After 100 laps it holds 5050 (the sum 1 to 100).

  6. Console.WriteLine($"Sum of 1..100 = {sum}");

    Prints the final total after the loop finished.

Output you will see

1 2 3 4 5 
10 5 0 
Sum of 1..100 = 5050

Common mistakes

  • Off-by-one errors: < vs <=.
  • Counting up while the condition expects counting down, creating an endless loop.
  • Declaring the total inside the loop, resetting it every lap.
Show the full program (15_for_loops/Program.cs)

//       (or from inside this folder:  dotnet run)

        {
            Console.Write(i + " ");
        }
        Console.WriteLine();

        // Counting down in steps of 5.
        for (int i = 10; i >= 0; i -= 5)
        {
            Console.Write(i + " ");

        int sum = 0;
        for (int i = 1; i <= 100; i++)
        {
            sum += i;

        Console.WriteLine($"Sum of 1..100 = {sum}");

Lesson 16

While loops

A while loop repeats as long as its condition stays true.

The big idea

A while loop checks its condition before every lap and keeps going while it is true. Use it when you do not know in advance how many laps you need ('keep asking until the password is right'). A do-while is the cousin that always runs once first.

Step by step through the code

  1. int n = 1;  while (n <= 5)

    Set up the counter, then loop while it is 5 or less.

  2. Console.Write(n + " "); n++;

    Print, then add 1. If you forget n++ the condition never becomes false and the loop runs forever.

  3. do { ... } while (countdown > 0);

    do-while: runs the body first, then checks the condition. So it always runs at least once. Here it counts 3, 2, 1.

  4. countdown--;

    Subtract 1 each lap so it eventually reaches 0 and stops.

  5. while (true)

    A loop with a condition that is always true. It would never end by itself...

  6. if (x == 4) break;

    ...so we use break to jump out of the loop immediately when x reaches 4.

  7. Console.WriteLine($"Broke out of the loop when x = {x}");

    Runs after the loop ended.

Output you will see

1 2 3 4 5 
do-while: 3
do-while: 2
do-while: 1
Broke out of the loop when x = 4

Common mistakes

  • Infinite loops (forgetting to change the variable).
  • Expecting do-while to skip the first run.
  • Using while(true) without any break.
Show the full program (16_while_loops/Program.cs)

The big idea

The conditional operator is a one-line if/else that produces a value. It is called ternary because it has three parts: the question, the answer if true, the answer if false.

8 is even

  • Chaining several ternaries until it is unreadable.
  • Using it to run statements (it only produces values; use if for that).

ToString("format") controls how a number is displayed.

The big idea

Raw numbers look ugly: 1234567.891. Formats let you show the same number as 1,234,567.89, a percentage, a currency, or hexadecimal. Formatting changes the text shown, not the stored number.

  2. n.ToString("F1")

  3. n.ToString("E2")

  8. 1234.5.ToString("C", us)

    C = currency. The culture (en-US) decides the symbol and separators: $1,234.50.

  9. $"Price: {19.5:F2}"

    The same format codes work inside interpolated strings after a colon.

1234567.9
1.23E+006
25.6%
FF
0007

$1,234.50

  • Thinking formatting changes the variable's value.
  • Forgetting that culture changes separators (comma vs dot).

Lesson 19

TryParse function

int.TryParse never throws: it returns true/false and gives the number through an out parameter.

The big idea

int.Parse crashes when the text is not a number. TryParse instead asks politely: it returns true if the conversion worked and false if not, and hands the number over through an out variable. This is how you handle real user input.

Step by step through the code

  1. string[] inputs = { "123", "abc", "4.5", "" };

    Four test strings: a valid int, letters, a decimal (not an int), and empty.

  2. foreach (string text in inputs)

    Test each one in turn.

  3. int.TryParse(text, out int value)

    Tries to convert text. Returns a bool for success, and out int value declares the variable that receives the number if it worked.

  4. if (...) { ... -> value }

    If success, we can safely use value: prints '123' -> 123.

  5. else { ... is not a valid int }

    If failure, we print a friendly message instead of crashing. abc, 4.5 and the empty string all end up here.

Output you will see

'123' -> 123
'abc' is not a valid int
'4.5' is not a valid int
'' is not a valid int

Common mistakes

  • Using the value without checking the returned bool.
  • Expecting TryParse to accept decimals when parsing an int.
  • Forgetting the out keyword.
Show the full program (19_tryparse/Program.cs)

Lesson 22

Verbatim string literal

Putting @ before a string turns off escape sequences, handy for file paths.

The big idea

Normally a backslash in a string starts an escape (\n, \t). Windows file paths are full of backslashes, so they get ugly. A string starting with @ treats backslashes as plain characters.

Step by step through the code

  1. string normal = "C:\\Users\\Maaz\\file.txt";

    In a normal string every backslash has to be doubled so C# does not think it is an escape.

  2. string verbatim = @"C:\Users\Maaz\file.txt";

    The @ turns off escapes, so you write the path exactly as it looks.

  3. normal == verbatim

    Both build the identical text, so this prints True.

  4. @"She said ""hi"" and left"

    Inside a verbatim string a quote is written as two quotes "", giving She said "hi" and left.

  5. string raw = """ ... """;

    A raw string literal (modern C#): three quotes at each end. Inside it, quotes and backslashes need no escaping at all, and it can span lines.

Output you will see

True
C:\Users\Maaz\file.txt
She said "hi" and left
Raw string: "quotes" and \backslashes\ are fine

Common mistakes

  • Forgetting the @ and getting an 'unrecognized escape' error.
  • Using \" inside a verbatim string (it does not work; use two quotes).

Lesson 23

String formatting

string.Format fills numbered placeholders {0}, {1}... with values.

The big idea

Before interpolation existed, this was how you built text from values. You write a template with numbered holes and then supply the values in order. It still appears in a lot of code and is useful for alignment.

Step by step through the code

  1. string.Format("{0} is {1} years old", name, age)

    {0} is replaced by the first value after the template (name), {1} by the second (age). Counting starts at 0.

  2. "{0:F1}"

    A format code after a colon: F1 shows one decimal, so 93.456 becomes 93.5.

  3. "[{0,10}] right-aligned"

    A positive number after the comma is a width: the value is padded on the left so it is right-aligned in 10 characters.

  4. "[{0,-10}] left-aligned"

    A negative width left-aligns the value (padding goes on the right).

  5. name.PadLeft(8, '*')

    A string method: pads on the left with '*' until the total length is 8: *****Ada.

  6. name.PadRight(8, '-')

    Same on the right: Ada-----.

Output you will see

Ada is 36 years old
Score: 93.5
[       Ada] right-aligned
[Ada       ] left-aligned
*****Ada Ada-----

Common mistakes

  • Using a placeholder number with no matching value (runtime error).
  • Starting the count at 1 instead of 0.

The modern, most readable way to build text. A $ before the opening quote turns the string into a template where anything inside { } is calculated and inserted.

Hypotenuse: 5.00
Date: 2026-11-17
Literal braces: {like this}

  • Forgetting the $, so the braces print literally.

String concatenation

Concatenation means joining strings together.

The big idea

Several ways to glue text, each with its own best use. An important fact: strings are immutable, meaning they can never be changed. Every join creates a brand new string.

Step by step through the code

  1. first + ", " + second + "!"

    The + operator joins pieces: Hello, World!.

  2. string.Concat(first, " ", second)

    A method that joins whatever you give it.

  3. string.Join("-", "a", "b", "c")

    Puts a separator between items: a-b-c. Very handy for lists.

  4. var sb = new System.Text.StringBuilder();

    A StringBuilder is an editable text buffer. Use it when building text inside a big loop, because plain + would create thousands of throwaway strings.

    Adds to the buffer. Appends can be chained one after another.

  6. sb.ToString().TrimEnd()

    Turns the buffer into a normal string, and TrimEnd removes the final trailing space: 1 2 3 4 5.

Output you will see

Hello, World!
Hello World
a-b-c
1 2 3 4 5

Common mistakes

  • Using + inside a loop that runs thousands of times (slow).
  • Forgetting a space between joined words.

Lesson 26

Empty string

"" is a real string with zero characters. null means "no string at all". They are different.

The big idea

Think of a string as a sheet of paper. An empty string is a blank sheet. null is having no sheet at all. Asking a blank sheet 'how long are you?' works (0). Asking 'no sheet' crashes unless you are careful.

Step by step through the code

  1. string empty = "";

    An empty string: exists, length 0.

  2. string alsoEmpty = string.Empty;

    Exactly the same thing, spelled so it is easier to read.

  3. string? nothing = null;

    null means no value. The ? after string tells C# 'this one is allowed to be null'.

  4. empty == alsoEmpty

    Prints True: both are the same empty text.

  5. nothing is null

    The safe way to check for null.

  6. nothing?.Length ?? -1

    ?. says 'only ask for Length if it is not null', which avoids a crash. ?? then supplies -1 when the left side was null.

  7. "   " == ""

    Spaces are characters! A string of spaces is not empty, so this is False.

Output you will see

empty length: 0
"" == string.Empty: True
nothing is null: True
length of null (safely): -1
spaces only equals empty? False

Common mistakes

  • Calling .Length directly on a null string (NullReferenceException).
  • Assuming whitespace equals empty.

String Equals function

The big idea

Two strings are equal only if every character matches, including capital letters. "Hello" and "hello" are different unless you explicitly say to ignore case.

True
True
Compare apple/banana: -1

  • Comparing a user's text case-sensitively and failing to match.

Lesson 28

String iteration looping

A string is a sequence of chars, so you can loop over it like an array.

The big idea

Because a string is a row of characters, you can visit them one at a time. Each character has a numbered position called an index, and counting starts at 0.

Step by step through the code

  1. string word = "C# rocks";

    8 characters: C, #, space, r, o, c, k, s.

  2. for (int i = 0; i < word.Length; i++)

    Loop i from 0 up to the last index (Length - 1). Using < not <= because the last valid index is Length - 1.

  3. word[i]

    Square brackets read the character at position i.

  4. foreach (char c in word)

    A simpler loop when you do not need the index: it hands you each char directly.

  5. word.ToLower()

    Lowercase first so 'A' and 'a' are treated the same.

  6. "aeiou".Contains(c)

    Asks 'is this char one of the vowels?'. Each hit adds 1 to vowels. Result for 'C# rocks': 1 (the o).

Output you will see

[0:C] [1:#] [2: ] [3:r] [4:o] [5:c] [6:k] [7:s] 
C.#. .r.o.c.k.s.
Vowels: 1

Common mistakes

  • Using i <= word.Length (index out of range).
  • Trying to assign word[0] = 'X' (strings are immutable).
Show the full program (28_string_iteration_looping/Program.cs)
// TOPIC: String iteration looping
// A string is a sequence of chars, so you can loop over it like an array.
//
// RUN:  dotnet run --project 28_string_iteration_looping
//       (or from inside this folder:  dotnet run)

class Program
{
    static void Main(string[] args)
    {

        // for loop with an index: word[i] is the character at position i (starting from 0).

        {

        {
            if ("aeiou".Contains(c)) vowels++;
        }
        Console.WriteLine($"Vowels: {vowels}");

        Console.ReadLine();   // keeps the window open until you press Enter
    }
}

The type before the function name (int, bool, string...) is what the function gives back with "return".

The big idea

A function can calculate something and hand it back, like a machine: ingredients in, product out. The type before the name is a promise about what comes out, and every path through the function must return a value of that type.

    No divisor found: it is prime. 7 → true, 9 → false (3 divides it).

  7. string Describe(int n) { return $"..."; }

    Returns text built from the number: 42 is even.

Square of 6: 36
Is 7 prime: True, is 9 prime: False
42 is even

Common mistakes

  • Not returning a value on every path (compile error).
  • Returning the wrong type.
  • Writing code after a return statement (it never runs).

Exercise: Custom TryParse

Write your own int.TryParse: validate text character by character without using Parse.

The big idea

Practice that combines loops, chars, out parameters and early returns. You rebuild the logic that int.TryParse uses internally.

Step by step through the code

  1. bool MyTryParse(string s, out int result)

    Returns true/false for success and gives the number through out.

  2. result = 0;

    An out parameter must always be assigned, so set it up front.

  3. if (string.IsNullOrEmpty(s)) return false;

    No text → not a number.

  4. if (s[0] == '-') { sign = -1; i = 1; }

    An optional leading sign: remember it and start checking digits after it.

  5. if (i == s.Length) return false;

    A sign alone, like -, is not a number.

  6. s[i] < '0' || s[i] > '9'

    Characters compare by their codes, so anything outside '0'..'9' is not a digit → return false.

  7. result = result * 10 + (s[i] - '0');

    The key trick: shift the number left one decimal place (×10) and add the new digit. s[i] - '0' converts the char '7' to the number 7. Reading 1, 2, 3 gives 1, 12, 123.

  8. result *= sign;

    Apply the minus at the end.

'-45' -> -45

// Write your own int.TryParse: validate text character by character without using Parse.
//
// RUN:  dotnet run --project 54_exercise_custom_tryparse
//       (or from inside this folder:  dotnet run)

class Program
{
    static void Main(string[] args)
    {
        string[] tests = { "123", "-45", "12a", "", "+7" };

        foreach (string s in tests)
        {
            if (MyTryParse(s, out int value)) Console.WriteLine($"'{s}' -> {value}");
            else Console.WriteLine($"'{s}' -> invalid");
        }

        bool MyTryParse(string s, out int result)
        {
            result = 0;
            if (string.IsNullOrEmpty(s)) return false;

            int i = 0, sign = 1;
            if (s[0] == '-') { sign = -1; i = 1; }       // optional leading sign
            else if (s[0] == '+') { i = 1; }
            if (i == s.Length) return false;             // a sign alone is not a number

            for (; i < s.Length; i++)
            {
                if (s[i] < '0' || s[i] > '9')            // every remaining char must be a digit
                {
                    result = 0;
                    return false;
                }
                result = result * 10 + (s[i] - '0');     // shift left one decimal place, add the new digit
            }

            result *= sign;
            return true;
        }

    }

Lesson 58

Exercise: Fix logic error

A logic error compiles and runs but gives a WRONG answer. A debugger helps you find it.

The big idea

Unlike syntax errors, logic errors give no warning. The program happily prints a wrong number. The only way to find them is to compare what you expect with what you get and step through.

Step by step through the code

  1. int[] numbers = { 10, 20, 30, 40 };

    The expected average is 100 / 4 = 25.

  3. int sum  /  int

  4. (double)sum / values.Length

    The fix: cast to double first (so decimals are kept) and divide by the real count.

  5. Fixed: 25

    Matches the expected result.

Output you will see

Buggy: 33   (expected 25)
Fixed: 25

Common mistakes

  • Trusting output without checking an expected value.
  • Fixing one bug and not noticing the second.

OOP: Operator overloading

You can define what +, -, ==, etc. mean for your own types.

The big idea

Normally C# only knows how to use +, -, ==, < on built-in things like numbers. Operator overloading lets you tell C# what those symbols mean for a type you made yourself, so a + b works for your Money.

Step by step through the code

  1. struct Money(decimal amount, string currency)

    We create our own type Money. It stores an amount and a currency. (A struct is a small value type, like int.)

  2. public decimal Amount { get; } = amount;

    A read-only property that remembers the amount given when the Money was created. { get; } means it can be read but not changed afterwards.

  3. public static Money operator +(Money x, Money y) => new(x.Amount + y.Amount, x.Currency);

    The rule for +. When C# sees Money + Money it calls this. It adds the two amounts and returns a new Money. public static is required for every operator.

  4. public static Money operator -(Money x, Money y) => ...

    Same idea for -: subtract the amounts.

  5. public static bool operator ==(Money x, Money y) => x.Amount == y.Amount && x.Currency == y.Currency;

    Defines what equal means: same amount AND same currency. It returns bool (true/false).

  6. public static bool operator !=(Money x, Money y) => !(x == y);

OOP: Equals and GetHashCode

By default two class objects are equal only if they are the SAME object (reference equality). Override Equals (and GetHashCode) to compare by content instead.

The big idea

For a class, C# thinks two objects are equal only if they are the exact same object in memory, even when all their values match. Equals lets you say 'equal means same values'.

Step by step through the code

  1. var a = new Point(1, 2);  var b = new Point(1, 2);

    Two separate objects that happen to hold the same numbers.

  2. a.Equals(b)

    Our overridden Equals compares X and Y, so the answer is True.

  3. ReferenceEquals(a, b)

    Asks 'are these literally the same object?'. No, they are two different objects, so False.

  4. public override bool Equals(object? obj) => obj is Point p && p.X == X && p.Y == Y;

    'Is the other thing a Point? If so, are X and Y the same?' obj is Point p checks the type and names it p in one step.

  5. public override int GetHashCode() => HashCode.Combine(X, Y);

    A hash code is a number summary of an object. HashSet and Dictionary use it to find things quickly. Rule: equal objects must have equal hash codes, so we build it from the same fields.

  6. set.Contains(b)

    b was never added, only a was. It still finds it because b equals a and has the same hash code, so True.

  7. class Plain(int v)

    A class with no overrides. new Plain(1).Equals(new Plain(1)) is False because they are two different objects.

Output you will see

a.Equals(b): True
Same object: False
HashSet finds equal point: True
Plain class equal: False

Common mistakes

  • Overriding Equals but not GetHashCode (HashSet/Dictionary will behave wrongly).
  • Using fields that change over time in GetHashCode.

ADVANCED: Delegates and lambda expressions

The big idea

A delegate is a variable that holds a method. A lambda is a quick way to write a small method without a name. Together they let you pass behaviour into other code.

  1. Func<int, int, int> add = (a, b) => a + b;

  5. delegate int Operation(int a, int b);

    Your own named delegate type: 'any method taking two ints and returning an int'.

  6. Operation op = Multiply;  op(6, 7)

    Point the delegate at a normal method and call it like a method: 42.

5

True
25
105
42

Common mistakes

  • Mixing up Func (returns a value) and Action (returns nothing).

The big idea

Pattern matching checks what kind of value you have and pulls out its data in the same step.

    Same idea in a normal if.

    {

        {

            {

                Circle c => $"circle area {Math.PI * c.R * c.R:F2}",
                Square { Side: > 2 } sq => $"large square {sq.Side}",
                _ => "something else"
            };
            Console.WriteLine(text);

        // "is" pattern in an if statement.
        object value = 7;

ADVANCED: async / await

ADVANCED: Threads, Tasks and parallel loops

    Start a worker thread, then Join waits for it to finish.

    Waits for the answer and gives it.

Counter with lock: 1000

  • Changing shared variables from several threads without lock/Interlocked.

        {
            int sum = 0;
            for (int i = 1; i <= 1000; i++) sum += i;
            return sum;
        });
