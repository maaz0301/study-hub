1. Your 30-second pitch

"A voice agent is a loop of three things. Speech-to-text turns the user's audio into text, an LLM agent decides what to do and calls tools (calendar, database, search) to actually act, and text-to-speech speaks the answer back. The hard engineering is not any single model. It is latency (under about one second to first audio), interruptions (barge-in), errors (mishearing, tool failures) and safety (confirming risky actions)."

4. Architecture: where each piece lives

Draw this on the whiteboard first. Everything in the shaded box is your server. The dashed line is the barge-in path.

  • Transport: WebSocket is simplest. WebRTC gives better echo handling and lower jitter for real-time audio.
  • Stateless workers: keep session state in Redis or a database, so any worker can continue a call and you can scale out.
  • Everything async: each box runs as a streaming task, so you can cancel any of them on barge-in.

5. Conversation state and memory

The LLM is stateless. Your server remembers the call and sends the relevant part each turn.

Session object

{
  "session_id": "c_8f21",
  "lang": "en",
  "history": [ ...last N turns... ],
  "summary": "Caller wants a table, 2 people",
  "slots": {"party": 2, "date": null, "time": null},
  "pending_confirmation": null,
  "tool_calls": 3,
  "started_at": "2026-11-24T06:20:00Z"
}

Rules that keep it working

  • Slot filling: track which required fields are still empty and ask for exactly one at a time.
  • Trim context: keep system prompt + last 6 to 10 turns + a rolling summary of older ones.
  • Shrink tool output: store the full result, give the model only the fields it needs.
  • Pending confirmation: remember the action awaiting a "yes" so a later "yes" is not misread.
  • Long-term memory: look up the caller by phone number and load only facts you are allowed to keep.

6. Latency budget (the number interviewers love)

Target: user stops talking → first audio back in about 1 second. Typical streaming numbers, not guarantees.

VAD 250STT 200LLM 400Tool 150TTS 150

≈ 1150 ms. Savings come from streaming everything: stream STT partials, stream LLM tokens into TTS sentence by sentence, and start speaking before the full answer exists.

7. Scenarios: "If we do this, what is the problem, and how do we solve it?"

A 6-step structure that works for ANY "what if" question
  1. Clarify: "Is this a phone call or web? How many users? What is the risk if it is wrong?"
  2. Impact: say what the user experiences and what it costs the business.
  3. Root cause: name the one underlying reason, not three guesses.
  4. Fix: a quick mitigation first, then the proper long-term solution.
  5. Trade-off: what the fix costs (latency, money, friction, complexity).
  6. Measure: the metric that proves it worked, and how you would test it before release.

  • Allow-list of tools; unknown names are rejected
    • 

  • Schema validation before every call
    • 

  • Confirm before writes, payments and deletes
    • 

  • Idempotency keys on every side effect
    • 

  • Tool output treated as data, not instructions
    • 

  • Least privilege: no tool both reads private data and sends it out
    • 

  • Step, time and spend caps per call
    • 

  • PII redacted from logs; retention limits
    • 

  • Recording consent and disclosure that it is an AI
    • 

  • Payments through DTMF or a secure link, not speech
    • 

  • Caller verification before account actions
    • 

  • Escalation path to a human at any time
    • 

  • Rate limiting and abuse detection per number
    • 

  • Secrets in a vault, never in prompts

13. Cascade vs speech-to-speech, and quick Q&A




Cascade (STT → LLM → TTS)Speech-to-speech model


LatencyHigher, tunable by streamingLowest, natural turn-taking


Control / debuggingHigh: you see the transcript, can swap any partLower: audio in, audio out


Tools & guardrailsEasy to log, validate and gateSupported but harder to inspect


CostPay per component, can mix cheap modelsOften higher per minute


Say this"I start with a cascade for control and observability, then move hot paths to speech-to-speech if latency demands it."






14. Glossary (say these words correctly)




TermMeaning

TTSText-to-speech

EndpointingDeciding the user has finished their turn

AECAcoustic echo cancellation: removes the speaker's sound from the mic


WERWord error rate: percent of words STT got wrong


TTFATime to first audio: end of user speech to first agent sound

Idempotency keyUnique key so repeating a request has the same effect as doing it once
